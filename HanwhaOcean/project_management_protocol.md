# 프로젝트 관리 프로토콜

> 외부 파트너사와 내부 개발팀이 참여하는 프로젝트 환경에서 관리 공수를 최소화하고 진행 현황과 히스토리 추적성을 확보하기 위한 운영 방안

---

## 1. 도구별 역할

도구 간 역할 중복과 문서 파편화를 방지하기 위한 역할 분담

| 도구 | 대상 | 보관/관리 내용 | 갱신 주기 |
| :--- | :--- | :--- | :--- |
| **Linear** | PM, 내부 개발팀 | **프로젝트 작업 및 이슈 통합 추적**<br>• 개발 작업, 비개발(PM/운영) 업무, 파트너사 의존성, 미결 안건 | 실시간 |
| **Outline** | 내부 전원 | **내부 기술 문서 (사내 보안)**<br>• 기술 스펙, 내부 아키텍처, 내부 회의록, 시스템 가이드 | 수시 |
| **Notion** | 내부 + 파트너사 | **외부 공유 문서**<br>• 파트너사 미팅 회의록, 외부 전달용 연동 가이드 | 파트너사 회의 시 |
| **Excel** | 고객사 / 경영진 | **고수준 일정표**<br>• 실시간 갱신하지 않음 | 주요 보고 일정 시 |
| **Slack / 유선** | 전원 | **실시간 소통 및 이슈 인입** | 상시 |

---

## 2. Linear 티켓 규칙

* 티켓 생성 시 반드시 `Project: [프로젝트명]` 지정
* 파트너사 관련 티켓
  * `external` 라벨 추가
  * 제목은 `[파트너사명]`으로 시작
  * 내부 구현 과정은 생략하고 인도받을 산출물만 티켓화 (예: `[한화로보틱스] 로봇팔 시제품 대여`)
* 미결 안건 및 의사결정 필요 티켓
  * `needs-decision` 라벨 추가 및 재검토 예정일(Due Date) 지정
  * 결정 완료 시 댓글에 사유·근거 링크를 남기고 라벨 제거

---

## 3. 운영 규칙

### 3.1 비공식 결정사항 기록
슬랙 DM, 구두 대화, 유선 통화로 합의된 내용은 별도 문서로 작성하지 않고 아래 2단계로 처리

* **1단계 (슬랙 공개 채널 공유)**: 합의 즉시 당사자가 슬랙 프로젝트 공개 채널에 1줄 요약 공유
  > *"방금 파트너사 박 부장님과 통화하여 웹훅 타임아웃은 5초로 처리하기로 합의했습니다."*
* **2단계 (티켓 댓글에 링크 첨부)**: 관련 Linear 티켓 댓글에 해당 **슬랙 메시지 링크**를 붙여넣음

### 3.2 고객사 보고 및 일정 관리
* **주간 보고**: 기존 포인트폼 양식을 유지하여 소통 채널로 발송
* **엑셀 스케줄표**: 실시간으로 유지보수하지 않으며, **주요 보고(경영진/고객사) 시점**에만 최신화하여 전달
