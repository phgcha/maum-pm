# 1. 사내 온톨로지란 무엇이고 무엇을 얻는가

> 기준일: 2026-11-02 (KST). 상위 문서 [README.md](./README.md)

---

## 1.1 정의

온톨로지는 클래스, 속성, 관계, 규칙을 명시한 공유 어휘다. 지식 그래프는 거기에 실제 인스턴스를 채운 결과물이다. 비슷한 개념과 구분하면 아래와 같다.

| 개념 | 담는 것 | 사내 예 |
| :--- | :--- | :--- |
| 용어집 | 용어와 정의 | 현행, 최신, 이력 같은 문서 상태 정의 |
| 분류체계 | 상하위 계층만 | Drive 폴더 번호 체계 |
| 데이터 카탈로그 | 자산 목록과 위치 | `document_index_snapshot.md` |
| 온톨로지 | 클래스, 관계, 규칙 | 결정은 Slack 요약 1줄과 Linear 댓글 링크로 기록한다는 규칙 |
| 지식 그래프 | 온톨로지에 인스턴스를 채운 것 | 그 규칙대로 연결된 실제 티켓, 메시지, 문서 |
| 운영 온톨로지 | 객체, 링크에 액션까지 | Palantir Foundry, Microsoft Fabric IQ, Atlassian Teamwork Graph 방식 |

용어 주의. "Enterprise Ontology"는 1998년 Uschold의 비즈니스 용어집, 2006년 Dietz의 DEMO 이론을 가리키기도 한다. 경영진 보고에서는 "도구 위에서 사람과 에이전트가 함께 읽고 행동하는 공유 객체 모델"로 정의하고 시작한다.

## 1.2 이미 존재하는 v0

저장소 인벤토리 결과 약 50개 엔터티 유형이 문서 곳곳에 흩어져 있다. 아래 요소가 이미 온톨로지의 구성 요소다.

| 기존 규약 | 온톨로지 요소 |
| :--- | :--- |
| 도구별 역할표 | 클래스별 기록 시스템 배정 |
| `external`, `needs-decision` 라벨 | 통제 어휘 |
| 구두 합의를 Slack 공개 채널에 1줄 요약, Linear 댓글에 링크 | Decision 클래스와 증거 관계 |
| 문서 상태 어휘 현행, 최신, 진행 중, 이력, 미확인 | Document 상태 속성 |
| 보안 1~3급 | 보안 속성과 노출 규칙 |
| 4단계 프로토콜 Local Anchor, Delta Query, Pointer Jump, Compaction | 에이전트에게 허용된 액션 정의 |
| 산출물 코드 `MAI-HO-00N Rev.X`, 마일스톤 M1~M5 | 식별자 체계 |

부족한 것은 이를 한곳에 버전 관리된 스키마로 적고, 도구 간 ID를 잇는 레지스트리를 두는 일이다.

## 1.3 얻는 것

| 효용 | 설명 |
| :--- | :--- |
| 도구 간 동일 개체 식별 | 이 Slack 메시지, 이 Linear 댓글, 이 Drive 파일이 같은 결정을 가리킨다는 사실은 어느 한 도구의 스키마로도 표현할 수 없음 |
| 추적성 | 계약 조항에서 사양서 리비전, 티켓, 결정, 산출물까지 한 줄로 연결. 지금은 스케줄 사본 4개가 서로 다른 기준일을 갖고, 상태 캐시의 작성 기준일과 델타 기록일이 어긋남 |
| 출처 달린 보고 자동화 | 주간 보고와 월례 보고 초안을 역량 질문의 답으로 생성하고 각 줄에 티켓 번호와 문서 링크를 첨부 |
| 인수인계와 1인 유지 위험 완화 | 한 사람의 머릿속 규칙이 파일이 되고, 온보딩 팩은 한 프로젝트에 대한 표준 질문 세트의 답이 됨 |
| 에이전트 정확도 | 아래 근거 참조 |

## 1.4 실패 원인은 기술이 아니라 조직

| 실패 패턴 | 설명 | 대응 |
| :--- | :--- | :--- |
| 스튜어드 부재 | 스튜어드와 정기 대조가 없으면 두 분기 안에 진부해짐. 실무자 추정 | 소유자 1명과 도구별 스튜어드 지정 |
| 전사 규모 착수 | 전사 프로젝트는 1년 안에 멈추는 경향. 실무자 추정 | 과제 1개 파일럿 |
| 소비자 미정 | 누가 어떤 질문에 쓰는지 정하기 전에 모델링 | 역량 질문 목록에서 시작 |
| 과잉 모델링 | 실제 질문도 없이 계층을 세밀하게 설계 | 핵심 클래스 12개로 제한, 확장 클래스는 프로젝트별 |
| 두 번째 진실 원천 | 콘텐츠를 복제한 그래프가 원본과 어긋남 | 포인터 그래프, 기록 시스템 하나 |
| 사이드 프로젝트 | 예산과 시간이 배정되지 않아 관심이 소멸 | 경영진 요청에 스튜어드 시간 명시 |

설계는 역량 질문, 즉 온톨로지가 답해야 할 질문 목록에서 시작한다. 역량 질문 방법은 [operations.md](./operations.md) 5절을 참조한다.
