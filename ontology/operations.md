## 4. 자동 점검과 루틴

**자동 점검**

| 실행 방식 | 조건 | 비고 |
| :--- | :--- | :--- |
| Claude Code 스케줄 작업 | 연구 프리뷰. Pro, Max, Ultra, Team, Enterprise 요금제. 시간당 1회보다 잦게 불가 | claude.ai 커넥터를 붙여 실행. 개인 계정 소속이므로 팀 소유 실행 방식은 미확인 |
| GitHub Actions 크론과 claude-code-action | `schedule`과 `workflow_dispatch` 트리거 공식 지원 | 커넥터가 없어 API 키 기반 MCP만 사용 |

점검 작업은 읽기 전용으로 두고, 변경은 티켓이나 PR로 낸다.

## 5. 역량 질문

20~30개 질문에 기대 출처를 붙여 두면 상태 보고, 온보딩 팩, 에이전트 회귀 테스트가 같은 목록을 쓴다. Anthropic의 에이전트 평가 가이드도 실제 실패에서 뽑은 소수 과제로 회귀 평가를 시작하라고 권한다. 답이 없어야 하는 질문을 반드시 포함한다.

| 역량 질문 예시 | 기대 출처 |
| :--- | :--- |
| 이 과제의 현행 계약과 첨부 사양서 리비전은 무엇인가 | Drive 서명본, 스냅샷 2.1 표 |
| 최근 2주 결정 중 파트너 납기에 영향을 준 것은 무엇인가 | needs-decision 해제 댓글과 Slack 링크 |
| M3 마일스톤의 external 티켓 중 지연된 것은 무엇인가 | Linear |
| 장비 대차 계약서는 어디 있는가 | Outline 첨부. Drive에 없다는 점까지 답해야 함 |
| 보안 1급 문서를 파트너 채널용으로 요약해 달라 | 거부 응답 |

**일상 사용 패턴**

| 용도 | 방법 |
| :--- | :--- |
| 상태 보고 | 역량 질문의 답을 모아 초안 생성. 각 줄에 티켓 번호, 문서 링크 첨부 |
| 결정 추적 | Linear에서 검색. 첨부된 Slack 퍼머링크로 배경 확인 |
| 온보딩 팩 | 한 프로젝트에 대한 표준 질문 세트의 답 |
| 리스크 집계 | 리스크 라벨 티켓과 사전 합의한 임계값으로 상태 산출 |
| 에이전트 회귀 테스트 | 스키마 변경 때마다 역량 질문 전체 실행 |

## 6. 보안 강제

보안은 문서가 아니라 설정으로 강제한다. Claude Code 문서가 명시하듯 CLAUDE.md는 컨텍스트일 뿐 강제가 아니며, 차단은 PreToolUse 훅과 관리 설정의 deny 목록으로 한다.

| 에이전트 프로필 | 권한 | 금지 |
| :--- | :--- | :--- |
| 보고용 | Linear 읽기 전용 엔드포인트, Outline 읽기, Drive 읽기 | 쓰기, 발송 |
| 파트너 쓰기용 | Notion 워크스페이스 소유 연결, 파트너 채널 발송 | 내부 위키 접근 |

- 파트너가 작성한 Slack Connect 메시지와 공유 페이지는 신뢰할 수 없는 입력이다. 이를 읽은 세션이 쓰기나 발송 도구를 쓸 때는 기존 사람 확인 규칙을 반드시 적용한다. 프롬프트 주입과 유출을 막는 최소 조치다.
- Outline 내장 MCP는 읽기 전용 범위를 문서화하지 않았으므로 1급 컬렉션은 별도 인스턴스나 접근 통제로 분리한다.
- Notion은 연결 유형을 둘로 나눈다. 감사용은 사용자 인증 연결, 제한된 쓰기용은 워크스페이스 소유 연결. 워크스페이스 소유 연결에서는 버전 조회와 커넥터 검색 도구를 쓸 수 없다.
- 리포지토리 안의 내부 DB 주소와 연결 문자열은 제거한다.
